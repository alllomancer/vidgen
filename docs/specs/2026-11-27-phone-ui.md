# Phone UI and shared job history

Jira: N/A
Date: 2026-11-27
Status: Approved
Last reviewed: 2026-11-27

## Problem

Renders can only be started and fetched from the Mac: the dashboard (`vidgen ui`) listens on 127.0.0.1 only and
signs every call with the SSH key in the Mac's ssh-agent. The user wants to send render commands from their phone and
download the rendered media there, while the full dashboard keeps running only on the Mac.

Job history is already server-side (DynamoDB, keyed by the client name = the signing key's comment), but three things
are Mac-only today:

- The watcher downloads only jobs in the Mac's `jobs.json` (`check_once`, `cli/vidgen.py`), so a job started from
  anywhere else would never land on the Mac.
- `avatar_name` and `krea_lora` of avatar-candidate jobs, and the chosen output file name, live only in `jobs.json`,
  so the Mac couldn't "pick" a candidate from a job it didn't start.
- Nothing but the Mac can sign requests.

## Approach

A second, small UI for the phone, served as a static page by the existing API (`GET /m`), that keeps its own ed25519
key in the browser and signs requests in the same SSHSIG format as `ssh-keygen -Y sign`. The phone key carries the
same comment as the Mac key, so both are the same client and see one history. Job metadata moves to the server, and
the Mac's watcher adopts jobs it didn't start. The Mac dashboard is unchanged apart from reading the new metadata.

Rejected: exposing `vidgen ui` to the phone over Tailscale/LAN (works only while the Mac is awake and running the
UI); hosting the phone page in S3/CloudFront (the SCP forbids public bucket access; the API route needs no new
infrastructure).

## Design

### Phone page

- `GET /m` returns `m.html` (inline CSS) and `GET /m/app.js` the script, both bundled in the Lambda package. These
  two are the only routes without a signature; they carry no data. Headers: `Cache-Control: no-cache`,
  `Content-Security-Policy: default-src 'self'; img-src 'self' https://*.amazonaws.com; media-src 'self'
  https://*.amazonaws.com; connect-src 'self' https://*.amazonaws.com; script-src 'self'; style-src 'self'
  'unsafe-inline'; frame-ancestors 'none'`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`.
- Same origin as the API, so the API needs no CORS. A `manifest.webmanifest` (also from the Lambda) lets it be
  added to the home screen.
- Screens: **Create** (video, photos, story; the same fields as the dashboard's basic form, avatar picker from
  `GET /avatars`), **History** (`GET /jobs`, progress and time left, Cancel, Re-run, Copy prompt, refresh every 10 s
  while visible), **Job** (results from `GET /jobs/{id}`: photos and videos shown inline from the presigned links,
  a Save link per file that opens the file so iOS Share → Save to Photos/Files works), **Avatars** (list, set
  default, add photos; training photos per docs/specs/2026-11-27-avatar-training-photos.md).
- Not on the phone: learning themes and dataset uploads (they point at Mac folders), LoRA file upload, Plan first,
  Restart worker, file pickers and Reveal in Finder.

### Key and signing

- First visit: `crypto.subtle.generateKey({name: "Ed25519"}, false, ["sign"])`. The private key is
  non-extractable; the CryptoKey pair is stored in IndexedDB. The page shows the public key as an
  `ssh-ed25519 AAAA... <comment>` line with a Copy button; the user types the comment (default: the one in the Mac's
  config, shown in `vidgen ui` → Settings → "Pair a phone" next to a QR code of the `/m` URL).
- Pairing: the user adds that line to `authorized_ssh_public_keys` in `terraform.tfvars` and runs `make apply`.
  Revoking = removing the line and `make apply`.
- Each call signs `vidgen-v1\n<METHOD>\n<rawPath>\n<ts>\n<nonce>\n<sha256 hex of body>` as SSHSIG v1, namespace
  `vidgen-api`, hash `sha512`, and sends `x-vidgen-timestamp`, `x-vidgen-nonce` (32 hex chars from
  `crypto.getRandomValues`) and `x-vidgen-signature` exactly as `cli/vidgen.py` `sign()` does. `_verify_sshsig` is
  not changed.
- 401 shows "This phone isn't paired yet" with the public key line again.

### Uploads from the phone

Photos (photos job input, avatar photos) go through the existing `POST /uploads` presigned PUT, then the normal
endpoint with `upload_keys`. The bucket gets a CORS rule: `AllowedOrigins = [<api origin>]`, `AllowedMethods =
[PUT]`, `AllowedHeaders = [content-type]`, `ExposeHeaders = [ETag]`, `MaxAgeSeconds = 3600`. Images are sent as
picked (HEIC is converted in the browser by drawing to a canvas and exporting JPEG at quality 0.92, because the API
accepts png/jpg/webp only).

### Job metadata on the server

- `POST /jobs` accepts an optional `meta` object: `out_name` (plain file name, max 128 chars, no `/` or leading
  `.`), `avatar_name` (avatar-name rule), `krea_lora` (bool), `source` (`"mac"`, `"cli"` or `"phone"`). Other keys
  → 400. Stored as the job item's `meta` attribute (JSON string), not part of `params`, so re-runs keep params and
  copy `meta` with `out_name` suffixed `-rerun-<id6>`.
- `GET /jobs` and `GET /jobs/{id}` return `meta` (`{}` when absent).
- `vidgen.py`, `ui.py` and the phone send `meta` on every create; `register_job` keeps writing `jobs.json` as now.
- `pick_candidate` (ui.py) and `vidgen avatar pick` fall back to the server's `meta.avatar_name`/`krea_lora` when the
  local record has none.

### Watcher adopts other devices' jobs

`check_once` first calls `GET /jobs` (one call per pass, the newest 100). Every job with status in `queued`,
`running`, `done` that is not in `jobs.json`, was created within the last `ADOPT_DAYS = 7` days and was not
previously dismissed is registered with `local_out(type, job_id, meta.out_name)` and `adopted: true`, then handled
like any other pending job. `jobs.json` gains a `dismissed` list so a job removed locally (`vidgen jobs forget`) isn't
re-adopted. Train and lora_preview jobs are adopted the same way.

## Acceptance Criteria

- When `GET /m` or `GET /m/app.js` is requested without signature headers, the API shall return 200 with the page or
  script and the headers listed above; every other route without a valid signature shall still return 401.
- The page's signature over a fixed key, method, path, timestamp, nonce and body shall be byte-identical to the
  SSHSIG produced by `ssh-keygen -Y sign -n vidgen-api` over the same message with the same key (ed25519 signatures
  are deterministic), and `_verify_sshsig` shall accept it.
- While the phone key and the Mac key have the same comment, `GET /jobs` signed by either shall return the same job
  list.
- When `POST /jobs` carries `meta` with an unknown key, an `out_name` containing `/` or longer than 128 chars, or an
  invalid `avatar_name`, the API shall return 400 and queue nothing.
- When a job is created with `meta`, `GET /jobs` and `GET /jobs/{id}` shall return that `meta`; a re-run shall carry
  the same `meta` with `out_name` `<base>-rerun-<first 6 of new id><ext>`.
- When the watcher runs and `GET /jobs` lists a `done` job created 2 days ago that isn't in `jobs.json` or `dismissed`,
  the watcher shall download it to `local_out(type, id, meta.out_name)` and record it as `downloaded` with
  `adopted: true`.
- If such a job was created more than 7 days ago or is in `dismissed`, then the watcher shall not adopt it.
- When an avatar job started from the phone is downloaded on the Mac, picking candidate N in the dashboard shall
  save it as `meta.avatar_name` with `meta.krea_lora`.
- When the phone uploads a photo with the presigned PUT, S3 shall accept it from the API origin and reject a PUT from
  any other origin's browser (CORS preflight fails).
- The phone page shall never send the private key anywhere and shall create it with `extractable: false`.

## Out of Scope

Push notifications when a job finishes; offline queueing; several people (each person is a client, as today);
learning themes, dataset upload, LoRA upload, Plan first and worker restart on the phone; Android-specific work beyond
testing in Chrome; a native app.

## Risks & Open Questions

- WebCrypto Ed25519 needs iOS 17+ Safari or a current Chrome. The page checks and says so if missing. (Resolved.)
- Safari can evict IndexedDB for sites not used for 7 days unless the page is added to the home screen; then the
  phone needs pairing again. The page says "Add to Home Screen to keep this phone paired". (Deferred: accept.)
- The two unauthenticated routes widen the API's surface slightly; they serve fixed bytes and touch no AWS service.
  API Gateway's existing throttling applies. (Resolved.)
- A key in a browser is weaker than ssh-agent: anyone holding the unlocked phone can render and download. Revocation
  is one `make apply`. (Deferred: accept for a personal project.)
- Presigned links expire after 1 hour; the Job screen re-fetches `GET /jobs/{id}` when opened. (Resolved.)
- Adopting jobs means the Mac also downloads phone renders; that's intended. (Resolved.)

## Testing

- Unit (tests/): `meta` validation and storage, re-run `meta` copy, `GET /m` unauthenticated while `GET /jobs`
  stays 401, watcher adoption (adopt, 7-day cut-off, dismissed), pick falling back to server meta.
- Signature parity: a Node test (`node --test`, no packages) runs `app.js`'s signer with a fixed test key and compares
  the result with `ssh-keygen -Y sign` output; `_verify_sshsig` accepts it.
- Manual: pair an iPhone, create a photos job from the phone, watch it in History on both devices, Save a photo to
  Photos, confirm the Mac's watcher downloaded it; revoke the key and see 401.

# vidgen UI: local dashboard

Jira: N/A
Date: 2026-11-09
Status: Approved
Last reviewed: 2026-11-09

## Problem

Everything happens in the terminal today. The user wants one place to see the server's
state and which model versions are deployed, browse the history of prompts with how long
each took (and run one again), and mark folders of clips as learning themes ahead of the
trainer.

## Approach

`vidgen ui`: a local web server (Python standard library, like the CLI) on
`127.0.0.1:8765` that serves one page and proxies to the existing signed API with the
user's SSH key. No public UI, no new login system. Two API additions: job history and
deployed model info, plus a server-side re-run.

## Design

- **Local server** (`cli/ui.py`, page `cli/ui.html`): binds 127.0.0.1 only; rejects requests
  whose Host header is not `127.0.0.1:<port>` or `localhost:<port>` (DNS rebinding) and
  `/api/*` calls without the per-session token (random, embedded in the served page, sent
  as `X-UI-Token`), so other sites in the browser cannot drive it. Endpoints:
  `GET /api/status`, `POST /api/wake`, `GET /api/jobs`, `POST /api/jobs/<id>/rerun`,
  `GET|POST /api/themes`, `POST /api/themes/<name>/rescan`, `DELETE /api/themes/<name>`,
  `POST /api/pick-folder` (macOS native folder picker via `osascript`; elsewhere 501 and the
  page asks for a typed path).
- **Server panel**: `GET /status` (instance, running minutes, queue, hold) plus a new
  `models` block: video/i2v/edit/vlm repos (Lambda env from the same Terraform variables the
  box's env file uses), Lightning repo + revision and MMAudio variant (parsed from the
  deployed `code/worker/models.py` in S3), worker code version (its S3 ETag) and deploy time
  (its LastModified). Refresh every 15 s; Wake button.
- **History panel**: new `GET /jobs?limit=N` (default 100, max 200): the client's jobs,
  newest first, via a new DynamoDB GSI `client-created` (hash `client`, range `created_at`).
  Each row: job_id, type, status, created/started/finished, `run_seconds` (finished -
  started), `wait_seconds` (started - created), `summary` (prompt; story first 120 chars;
  photo scenes; avatar description; describe instructions), `details` (seconds, avatars,
  count, aspect, shots), error. The UI adds the local download path from
  `~/.vidgen/jobs.json`. Filter by type and text. Records expire with the jobs table TTL
  (30 days).
- **Re-run**: new `POST /jobs/{job_id}/rerun` copies the original job's validated params
  into a new queued job (same seed if one was given) and starts the instance, like
  `POST /jobs`. The UI registers it in `~/.vidgen/jobs.json` so the watcher downloads it.
- **Learning panel**: themes in `~/.vidgen/themes.json`: `{name, kind, folder, trigger,
  created_at, scan}`. Kinds and guidance: character 10-40 clips (+ photos), style 30-100,
  motion 20-60, place 15-40. Scan (recursive): clips (mp4, mov, webm, mkv), photos (png, jpg,
  jpeg, webp), durations via ffprobe when installed, total minutes, problems: below the
  minimum, above the maximum (warning), files over 2 GB, clips over 60 s (will be cut),
  unsupported files (count). Name: 1-32 chars `a-z 0-9 - _`; trigger default `vgn_<name>`.
  Upload and Train buttons render disabled: "trainer not deployed yet".
- **CLI**: `vidgen ui [--port 8765] [--no-browser]`.

## Acceptance Criteria

- When `vidgen ui` runs, the system shall serve the page on 127.0.0.1:8765 and open it in
  the default browser (unless `--no-browser`).
- If a request's Host header is not 127.0.0.1:<port> or localhost:<port>, then the local
  server shall return 403; if an `/api/*` request lacks the session token, it shall return 403.
- When `GET /status` is called, the response shall include `models` with `video`, `i2v`,
  `edit`, `vlm`, `lightning` (repo, revision), `mmaudio`, `worker_code` (version, deployed_at).
- When `GET /jobs` is called, the system shall return at most `limit` of the caller's jobs
  only, newest first, each with `run_seconds` and `wait_seconds` when the timestamps exist.
- When `POST /jobs/{id}/rerun` is called for the caller's job, the system shall queue a new
  job with the same type and params and return 202 with the new job_id; for another
  client's or a missing job it shall return 404.
- When a folder is registered as a `character` theme with 6 clips, the scan shall report 6
  clips and the problem "6 clips; character needs 10-40".
- If a theme name is invalid or already used, then the local server shall return 400.

## Out of Scope

Submitting new jobs from the UI, dataset upload, training, hosting the UI remotely,
multi-user access.

## Risks & Open Questions

- GSI backfill (Resolved): adding a GSI to the on-demand jobs table is an in-place update;
  existing items are indexed automatically (all have `client` and `created_at`).
- Model info drift (Resolved): repos come from the same Terraform variables as the box's env
  file; Lightning/MMAudio come from the deployed worker code itself.
- Local server exposure (Resolved): localhost bind + Host check + session token.

## Testing

- Unit (stubbed AWS): `list_jobs` ordering, durations, client isolation; rerun copies
  params; status `models` parsing. Local server: theme scan/problems, name validation, Host
  and token checks.
- Browser: run `vidgen ui --no-browser` in the preview browser after deploy; check all three
  panels against the live API.
